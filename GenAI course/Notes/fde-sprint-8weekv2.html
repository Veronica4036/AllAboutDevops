▸ Start here — how to use this plan (read once)

What you are building. Two portfolio projects. policy-rag (Weeks 1–2): a question-answering service over insurance policy documents, with a real evaluation harness and enterprise security — login, per-role document access, audit logging, and inference inside your own AWS account. incident-copilot (Weeks 3–4): an agent that investigates production alerts using your runbooks and incident history, proposes a root cause, and waits for human approval before acting. Neither repo exists yet — you create both.

How each day works. A morning study block (1.5h) that teaches exactly what the evening build block (2.5h) needs, so nothing is learned in the abstract. Weekends are longer build blocks. Every task carries a Done when line — that is the test for whether it is finished. Do not tick a box until that test passes.

Links. Blue ↗ links under a task are primary sources for that task. The Key Sources panel at the bottom groups them by topic, and the Glossary explains every term the plan uses. Clicking a link never ticks the checkbox.

Before Monday. Do the Week 0 setup weekend first — API keys, Docker, deploy target, Bedrock access, three policy PDFs, both repos. Skipping it means discovering a billing or access problem on Monday night.

If you fall behind. Cut scope inside the day rather than pushing the calendar. If you are more than two days behind at the end of Week 3, switch to the 16-week plan instead of grinding.
